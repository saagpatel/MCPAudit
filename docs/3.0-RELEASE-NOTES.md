# MCPAudit 3.0.0 Release

Release status: approved
Publication decision: GO

MCPAudit 3.0.0 is the boundary release: it removes the surfaces that 2.11 and
2.12 deprecated with warnings, splits the package into three lockstep
distributions, and makes withheld pin baselines fail the checks that asked for
them. This release authorizes the exact release-state source for review and
publication gating; tag, GitHub Release, all three PyPI projects, MCP Registry,
runtime, deployment, adoption, and user-acceptance claims still require their
own live readbacks.

## What changed

- **Package split.** Core stays `mcp-audits` (`mcp_audit`, with the
  `mcp-audit` and `mcp-audits` commands). The 34 lab and SafeForge modules and
  the session/resume scenario corpus move to `mcp-audits-labs`
  (`mcp_audit_labs`). Proof Before Action's five modules move to
  `mcp-audits-proof` (`proof_before_action`), which owns the
  `proof-before-action` command and imports nothing from core. All three
  release in lockstep with one version. Core gains the `labs`, `proof` and
  `all` extras, which pin the satellites exactly; labs pins
  `mcp-audits==VERSION` exactly. Without labs, `lab` and `safeforge` exit 2
  with the install notice.
- **`scan` is a legacy interceptor over `check`.** Forms classified as
  preserved or explicitly narrowed print one notice and run the printed
  `check` command through `check`'s parser, output and exit handling. Forms
  that could silently lose coverage print an inexact replacement and exit 2
  without scanning: bare `scan`, connected defaults, `--json PATH` and
  comma-separated `--clients`. The legacy engine path is removed.
- **D22 exact translation.** Static discovering `scan` forms, including the
  2.11 hook form, translate to
  `check --include-discovered --scan-compatible-sources`. The hidden selector
  reproduces `scan`'s server selection exactly: every Claude Code project
  scope, no Cursor project file, cwd `.mcp.json` and `.vscode/mcp.json`,
  whole-file loss on a malformed project entry, `scan`'s server-level dedup,
  and an empty result for a present file without a server map, all subject to
  `check`'s source limits. It requires `--include-discovered` and is rejected
  with `--config`, `--project`, `--config-only`, `--connect` and
  `--connect-all`. It is supported for all of 3.x. Plain `check` keeps its
  stricter selection and remains the recommended spelling.
- **Deletions.** The deprecated `monitor` command and module, the frozen
  `_run_scan_core` function, the `mcp_audit.cli` private-name shim, the
  `_run_scan`/`_parse_clients` re-exports, and 11 hidden top-level aliases
  (eight lab topics, `safeforge-preinstall`, `safeforge-run` and `skillscan`)
  are removed. `pin` stays as a visible alias for `baseline pin`.
- **`serve` static default.** The `scan_mcp_servers` tool defaults to
  `connect=false`; pass `connect=true` to connect. `skip_connect=true` still
  disables connections. Every other `serve` tool keeps its reach, and each
  description states it.
- **v1 pins withheld, and the run-failure gate.** Schema v1 baselines are never
  compared, with or without trusted keys, and never satisfy `require.pins`.
  `check` and `shadow` exit 2 after writing reports when any requested
  pin-dependent check (pin, canary, escalation, provenance, integrity,
  artifact verification or download) has a withheld baseline, and
  `policy_result` records the failure even without `--policy`. An explicit
  `fail_on.pin_baseline_withheld: false` is ignored with a loader warning.
  `watch` keeps running and renders the warning on every scan. `pin --refresh`
  reviews v1 tools as new with their full current surface.
- **Compatibility SARIF skip results.** The compatibility profile emits one
  warning-level `MCP-CH-CONFIG-PARSE-FAILURE` result per skipped discovered
  source, with its reason, location and `--config FILE` remedy, including
  translated static scans. Existing notifications, exit codes and extended
  results are unchanged.
- **Three-distribution, commit-first release tooling.** Publishing dispatches
  on an approved commit and version, builds and smokes all six wheels and
  sdists with exact build constraints, uploads core, labs and Proof in order
  with a PyPI readback after each, and resumes only missing files from the
  original run's retained bytes. A committed `release/distributions.json`
  must match the release-controls copy byte for byte, and every version
  outside 2.x requires the three-distribution contract. The tag, GitHub
  Release and Registry entry advance only after all six files verify.

## Breaking changes

The [3.0 migration guide](3.0-MIGRATION.md) is the authoritative list of every
break, its replacement, and how to detect it on 2.12. The
[changelog](../CHANGELOG.md) records each break under `Breaking`. Report
formats and `schema_version` do not change; some reports gain additive
warnings and SARIF results.

## Upgrade notes

- Install core with `uv tool install mcp-audits`, labs with
  `uv tool install 'mcp-audits[labs]'`, and Proof Before Action as its own
  tool with `uv tool install mcp-audits-proof`, which puts
  `proof-before-action` on PATH.
- Your Action ref and hook `rev` decide what runs, not your local install. A
  2.x ref keeps running its 2.x release until you bump it. Bump the Action ref
  and its `version` input together: a 2.10 or 2.11 ref still assembles `scan`
  grammar and fails with a 3.x `version`. The 3.x Action installs core only,
  so `lab` commands through `args` are not supported. See
  [Pre-commit hook and GitHub Action](3.0-MIGRATION.md#pre-commit-hook-and-github-action).
- Reference the release by the exact `v3.0.0` tag or its reviewed commit.
  There is no moving `v3` tag, and none will be created.
- Refresh schema v1 pins on 2.12 before upgrading
  (`mcp-audit pin --refresh SERVER`, review, then `--apply`); 2.12 is the last
  line that can diff against a v1 hash.

## 2.x support

2.x receives security-only fixes, with no features, on `release/2.x` for 120
calendar days after 3.0.0, until 2027-03-01. The 2.x line (`release/2.x`)
receives security fixes only until that date. Backports cover the package, the
Action and the pre-commit hook. See
[continuous integration](guides/ci.md#command-grammar-and-release-tags).

## Public-surface boundary and rollback

Release metadata for all three distributions, the Registry descriptor, Action
examples, pre-commit example, the CI guide, and `docs/release-state.json`
identify 3.0.0; source references do not prove public availability. Until
publication completes, those source references are proposed release identities
rather than proof that any public artifact or Registry entry exists. Retain
`mcp-audits==2.12.0` as the rollback pin and verify installed command identity
after rollback; a rollback to 2.12.0 first runs
`pip uninstall mcp-audits-labs mcp-audits-proof` if either was installed, then
installs the pin (both 2.12.0 core and 3.0.0 Proof own the `proof-before-action`
script, so uninstalling Proof after the downgrade would remove it).

## Compatibility and required closure

Python 3.11–3.13 and the MCP SDK range `mcp>=2.2.0,<3.0` remain supported.
`schema_version` is unchanged.

Tag, GitHub Release, all three PyPI projects, MCP Registry, runtime,
deployment, adoption, and user-acceptance claims require their own live
readbacks. The owner creates the `v3.0.0` tag only after all six files verify.

Local tests and repository consistency establish only the behavior exercised
and release metadata consistency. They do not establish publication, live
third-party interoperability, deployment, adoption, or human outcomes.
