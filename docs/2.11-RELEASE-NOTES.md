# MCPAudit 2.11.0 Candidate

Release status: candidate
Publication decision: NO-GO

MCPAudit 2.11.0 is a candidate for review and CI validation only. This source
state does not authorize tagging, publication, Registry mutation, deployment,
or claims of downstream adoption. Merging this candidate does not authorize
the release-state flip, which belongs in a separate reviewed PR.

## Upgrade notes

- Reading a legacy v1 pin emits `pin_schema_outdated` with a migration hint:
  `mcp-audit pin --refresh SERVER --apply` after review. Preview with
  `mcp-audit pin --refresh SERVER`, review the proposed changes, then apply.
  Both commands can start the selected configured server. The warning also
  appears in `pin --status` terminal and JSON output. v1 pin support is
  deprecated and scheduled for removal in 3.0; see [Pinning](guides/pinning.md).
- Connected large-fleet CLI scans can emit the additive `worker_process_failed`
  scan warning code when worker results are missing. Consumers must tolerate
  the new code; explicit failed audits do not establish completed checks.
- Argv elements whose readings expose a secret label and inline delimiter are
  now withheld whole, including escape-supplied and fullwidth delimiters that
  previously left part of a value visible. Expect more `<redacted>` markers in
  those rare cases. Flag names are NFKC-normalized before flag/value pairing;
  argv detection also reads ESC ESC as a terminal does, restarting at the second
  ESC without changing control-stripping semantics.
- Long, terminated OSC 8 terminal hyperlinks now show their redacted URL instead
  of `<redacted>` for the whole field. The URI goes through URL redaction and
  link text through free-text detection. Malformed frames retain the conservative
  fallback. Redaction remains best-effort; review reports before sharing.

## Included capability groups

- Structural argv redaction treats each element as a unit: an element whose
  readings expose a secret label and inline delimiter is withheld whole.
  NFKC-normalized flag names govern flag/value pairing, so ordinary options such
  as `--format=token` preserve following flags. Detection includes terminal-style
  ESC ESC readings and separator-delimited values within one element.
- OSC 8 hyperlinks are parsed structurally, with URL redaction for URI
  credentials and free-text detection for link text. Long plain hyperlinks
  survive instead of triggering wholesale withholding. An escape-dense
  guardrail, bounded reading budgets, and linear-work regressions keep densely
  escaped field redaction linear.
- Connected `mcp-audit scan` runs of more than 256 servers shard per-server work
  across up to eight worker processes on supported POSIX hosts, for stateless
  options only. Fleet checks and report finalization stay in the parent, with
  the scan-wide connection limit enforced. Stateful pin, canary, LLM, and
  package-verification modes, `--skip-connect` scans, and library callers retain
  the single-process path. Missing worker results produce failed audits and
  `worker_process_failed` warnings.
- Single-process analysis and report rendering avoid repeated empty-metadata
  work, coverage construction, config copies, and JSON conversions, reuse short
  keyword matches, and stream JSON audits from a shared redacted snapshot.
  A conservative plain-ASCII report-text fast path is tested for equivalence
  to the full redactor; report fields and formatting are preserved.
- The calibrated hostile-performance gate covers 100,000-server `--skip-connect`
  scans against the 10 s target, a full 1 MiB description under `--ssrf-check`,
  and hostile servers within timeout + 4.5 s, with zero leftover processes or
  groups in every profile. Runner calibration scales time ceilings while
  retaining the published targets, RSS, and coverage requirements; these are
  synthetic gate bounds, not universal workstation performance guarantees.
- Legacy v1 pin reads warn with the `pin --refresh` migration command rather
  than silently retaining reduced coverage. v1 support remains available in
  2.11 and is scheduled for removal in 3.0.
- Static schema header checks follow local `$ref`, `allOf`, `anyOf`, and `oneOf`
  within bounded depth and work. Unresolved, malformed, cyclic, or exhausted
  branches retain incomplete coverage, while known header-type violations
  survive unrelated unresolved alternatives. No remote schemas are fetched.
- The [3.0 boundary proposal](3.0-BOUNDARY-PROPOSAL.md) is published for review.
  None of its proposed package splits, command changes, or removals ship in 2.11.
- Release tests derive candidate or published identities from release state.
  A regression test pins the no-cache requirement on publish workflows, and
  transport hygiene failures include process-group teardown diagnostics and
  `ps -g` output. These checks do not publish or dismiss code-scanning alerts.

## Published-version boundary and rollback

The published version remains 2.10.1. `server.json`, Action examples,
pre-commit examples, and the CI guide continue to name that published
package/tag. Retain `mcp-audits==2.10.1` as the rollback pin and verify
installed command identity after rollback. Source metadata alone is not
publication readback.

## Compatibility and required closure

The distribution remains `mcp-audits`; installed commands remain `mcp-audit`,
`mcp-audits`, and `proof-before-action`. Python 3.11–3.13 and the MCP SDK range
`mcp>=2.2.0,<3.0` remain supported. Existing 2.x report contracts remain
additive, with `schema_version` unchanged.

Before publication, land the reviewed candidate with exact-head CI and
security review, build and verify wheel/sdist artifacts from the final clean
revision, and promote release-state metadata in a separately reviewed PR.
Tagging and publishing need separate approval naming the exact release commit
and tag; independently read back PyPI, GitHub Release, and MCP Registry state.

Local tests and repository consistency establish only the behavior exercised
and candidate metadata consistency. They do not establish publication, live
third-party interoperability, deployment, adoption, or human outcomes. A clean
canary describes only its bounded in-session exercise.
